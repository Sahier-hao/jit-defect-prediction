## 3. 一次30–45分钟的需求讨论议程（建议）

| 用时 | 讨论 | 需记录的结论 |
|---|---|---|
| 5分钟 | 我们解决谁的什么问题，哪些仍是假设 | 主用户候选、访谈安排和反例 |
| 10分钟 | 首个MVP与最终两类八模型范围 | 首轮选中／暂缓Story、理由、依赖 |
| 10分钟 | 演示原型与失败状态 | 需要修改的入口、解释与状态文案 |
| 10分钟 | 标签／切分／成本、架构与两项NFR | 确认值及还需Pilot／教师核对的事项 |
| 5分钟 | 认领任务与阶段判断 | owner/reviewer/截止，以及是否满足进入实现条件 |

## 4. 进入首轮实现前应有的材料

- 有真实调研或有根据的场景核对；若暂时不能访谈，明确课程范围假设和未验证风险，不伪称调研完成。
- 主用户、首轮链路、最终硬性要求、可选项及排除项有实际范围决定。
- 首轮故事有正常／异常验收，失败和空状态可解释；重要参数有决定或具体 Pilot 任务。
- 架构、数据库、长任务、模型来源和时间／标签协议不冲突；两项质量验证有可执行测量条件。
- OpenSpec 提案及任务可追溯，团队留有真实评审意见；看板负责人和复核人实际认领。

这个条件表用于团队判断准备程度，不是一条新的用户授权限制，也不能用自动勾选替代实际证据。
