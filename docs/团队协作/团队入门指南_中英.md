## 先理解我们要做什么 / What we are building

我们要做一个帮助代码评审员决定“先检查哪个提交”的工具。系统学习历史代码变更，给一次提交输出风险分数和解释，再在列表里展示。

We are building a tool that helps code reviewers decide which commits to inspect first. It learns from historical code changes, estimates a commit's defect risk, and shows the score with an explanation.

预测不是确定结论，也不证明某个开发者能力差。课程原型由用户手动触发预测，不承诺自动阻止合并。

A risk score is a prediction, not proof that a commit is defective or that a developer is less capable. The course MVP uses manually triggered predictions.

## 第一次一起做的事 / First session

建议安排一次 30 分钟的共同入门，不要求任何人事先安装工具。

Suggested first session: 30 minutes together; no tool installation is required in advance.

| 时间 / Time | 动作 / Action | 产物 / Result |
|---|---|---|
| 0-10 分钟 / min | 每人用一句话解释产品；互相问不理解的词。Each person describes the product and asks about unfamiliar terms. | 四人都能说明“为评审员排序提交”。Everyone can explain that the tool prioritizes commits for reviewers. |
| 10-20 分钟 / min | 打开核心流程，走一次“无模型”和“有模型”的路径。Walk through the workflow with and without an available model. | 记下两个疑问。Record two questions. |
| 20-30 分钟 / min | 每人认领一个任务，指定另一人复核。Each person claims one task and chooses another member as reviewer. | 填好任务负责人、复核人和预期产物。Record owner, reviewer, and expected output. |

新成员可以认领任意一个任务，也应参与技术实现；不因为用英语交流就只承担翻译、测试或文档。

The new member can choose any task and should also take part in implementation. Using English does not restrict anyone to translation, testing, or documentation.

## 共同协作方式 / How we work together

- **职责不等于专长 / Roles are not specialties.** 荀浩继续协调进度，徐卓航继续组织需求优先级；技术任务按大小认领、结对和轮换。Xun Hao coordinates progress, and Xu Zhuohang coordinates product priorities. Technical tasks are claimed, paired, and rotated.
- **每个任务有负责人和复核人 / Every task has an owner and a reviewer.** 负责人整理产物，复核人按完成标准检查；两人都可以一起学习。The owner prepares the output, and another member checks it against the acceptance criteria. Both can learn together.
- **共享信息要让四人都读得懂 / Shared information must be readable by everyone.** 任务标题、完成标准、阻塞和会议结论提供英文；中文课程材料可以保留。Use English for task titles, acceptance criteria, blockers, and meeting decisions; Chinese course documents can remain in Chinese.
- **先做一个可验证的小结果 / Start with a small verifiable result.** 一个任务以 1-2 小时的首次尝试为目标，太大就拆分。Aim for a first attempt of 1-2 hours, and split tasks that are too large.
- **卡住时贴出具体证据 / Share evidence when blocked.** 写出已尝试步骤、错误原文和期望结果。Record what you tried, the exact error, and the expected result.

这些补充是 2026-10-04 的协作草案，仍需全组一起复核。既有非作者审阅和过程证据要求继续按团队约定执行。

These additions are a collaboration draft dated 2026-10-04 and still need review by all four members. Existing independent-review and course-evidence requirements are described in the team agreement.

## 常见词 / Small glossary

| 中文 | English | Plain explanation |
|---|---|---|
| 提交 | Commit | A recorded set of code changes. |
| 缺陷修复提交 | Bug-fixing commit | A change that repairs a bug; a keyword match alone is only a candidate. |
| 缺陷引入提交 | Bug-inducing commit | An earlier change suspected of introducing code later fixed. |
| SZZ | SZZ | A method that traces lines changed by a bug fix back through history; its labels can be noisy. |
| 特征 | Feature | A numeric description of a change, such as the number of modified files. |
| Kamei 14 维 | Kamei 14 features | The 14 change metrics required by the course project. |
| 训练集 | Training set | Earlier examples used to learn model parameters. |
| 测试集 | Test set | Later held-out examples used to measure the final model. |
| 时间切分 | Temporal split | Earlier changes are used for training, and later changes for testing. |
| 风险分数 | Risk score | A model estimate used to prioritize review, not a guaranteed outcome. |
| 验收标准 | Acceptance criteria | Observable conditions that tell us whether a task or story is complete. |
| MVP | Minimum viable product | The smallest working flow that demonstrates value to the user. |
| Effort-aware | Effort-aware evaluation | Evaluation under a review-work budget; 20% effort does not necessarily mean 20% of commits. |

术语依据现有[产品需求文档](../需求与设计/产品需求文档.md)和[JIT 调研](../调研资料/JIT学术与竞品调研_第一周.md)，不代表本项目已经实现这些能力。
