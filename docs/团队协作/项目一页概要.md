# JIT 缺陷预测系统：一页概要

厚积薄发 · 四人初学者团队 · Sprint0 · v0.6讨论稿 · 2026-10-04

## 解决什么问题

主要用户候选是代码评审员。待验证的问题：当多个变更等待评审且时间有限时，哪些信息能帮助其安排顺序、找到值得检查的上下文？课程提出了提交级预测场景，真实痛点、工作单位和使用意愿仍需访谈验证。

## 用户怎么用

算法使用者准备一个真实仓库的数据与模型；评审者选择提交，查看风险分数、模型来源和关键特征，再决定是否深入检查。分数不是缺陷确认，解释不是因果证明，首轮由用户手动触发。

`仓库接入与状态 → 解析、候选修复与SZZ → 14维特征及标签快照 → 时间切分与基线训练 → 双指标及模型登记 → 风险列表、详情与解释`
