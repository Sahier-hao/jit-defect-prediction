**定位修正：这是需求确认前提前开展的技术试做，不是已批准的产品架构、Sprint 1 交付或前置工作完成证据。** 当前项目工作回到[需求与产品设计](../团队协作/Sprint0前置工作清单.md)。下文保留实际软件行为及运行方式供讨论，最终范围以真实调研和评审后的需求为准。

## 启动

在项目根目录的 PowerShell 中执行。Python 需要 3.11 或更高版本，Node 需要满足项目锁定的 Vite 版本要求（本次验证使用 Node 24）。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
npm --prefix frontend ci --cache frontend/.cache/npm --no-audit --no-fund
npm --prefix frontend run build
.\.venv\Scripts\python.exe -m uvicorn jit_defect.api:app --host 127.0.0.1 --port 8000
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。点击 `Load synthetic demo`，再点击 `Train baseline`，即可查看风险列表；点击每行右侧箭头查看解释。API 参考位于 [/docs](http://127.0.0.1:8000/docs)。

如果当前 Python 环境已经具备依赖、前端也已构建，可直接使用 `python -m uvicorn jit_defect.api:app --host 127.0.0.1 --port 8000`。停止服务使用 Ctrl+C。默认仅监听本机。

开发前端时，在另一个 PowerShell 中执行 `npm --prefix frontend run dev`；开发服务器将 `/api` 转发到本机 8000 端口。

## CSV 格式

必填表头：

```text
commit_id,committed_at,label,ns,nd,nf,entropy,la,ld,lt,fix,ndev,age,nuc,exp,rexp,sexp
```

可额外提供 `message`。使用 UTF-8（允许 BOM）、唯一提交 ID、带时区的 ISO-8601 时间。例如 `2025-01-01T08:00:00+08:00` 会归一到 UTC；不接受缺少时区的日期。

- `label` 只能是 `0`、`1`、`unknown` 或空值；unknown 保留，不转成非缺陷。
- 14 个特征必须全部存在，且为有限非负数；`fix` 为 0 或 1。缺失特征不自动填零。
- `fix` 描述当前变更是否用于修复；`label` 描述缺陷引入标签，两者不同。
- 最大 5 MiB、20,000 条记录。重复 ID、重复表头、额外列、错误列数或非法值会使整个导入失败，不留下部分数据。
- 界面要求提供数据名称、来源和标签策略；合成数据必须显式标记。导入器保存原始 CSV 的 SHA-256，但不能独立证明外部标签的 SZZ 质量或观察窗口成熟度。

合成样例可通过界面下载，或在根目录生成：

```powershell
python -m jit_defect.demo --output data/sample/synthetic_features.csv
```

这份样例是生成的特征，不是从 ActiveMQ 提取的数据。真实项目特征提取和 SZZ 是后续独立工作。

## 数据与模型设计

| 文件／表 | 作用 |
|---|---|
| [data.py](../../jit_defect/data.py) | CSV 校验、UTC 时间归一、显式未知标签 |
| [learning.py](../../jit_defect/learning.py) | 时间切分、训练集标准化、逻辑回归、评价和精确解释 |
| [store.py](../../jit_defect/store.py) | SQLAlchemy 表结构与存储初始化 |
| [api.py](../../jit_defect/api.py) | 导入、训练、模型、风险、详情及前端服务 |
| `datasets` | 来源、标签策略、原始文件哈希、合成标记与计数 |
| `commits` | 按数据集与提交 ID 唯一保存时间、标签、14 维特征及消息 |
| `registered_models` | 模型版本、配置、时间窗口、数据哈希、指标与逐条测试预测 |
| `predictions` | 按模型保存分数与 training／holdout 范围，用于全局排序分页 |

默认数据库为 `runtime/jit.sqlite3`，模型为 `runtime/models/<model_id>.joblib`；重启后仍可读取。每次训练产生新 ID，不覆盖旧模型。文件先写入临时位置，再登记模型与预测；失败时回滚数据库并清理本次模型文件。读取时校验模型文件哈希，缺失或损坏会返回明确错误。

可用 `JIT_DATA_DIR` 改变本地数据目录。可通过 `JIT_DATABASE_URL` 配置其他 SQLAlchemy 数据库，但 PostgreSQL 尚未集成验证，需安装 `.[postgres]` 并另行验证；不把“可配置”当作已经支持的验收结果。

模型文件仅由服务产生；当前没有上传或导入外部 joblib 模型的入口。运行数据、构建产物和测试输出放在被忽略的目录中；本次没有运行 Git 命令。

## 训练和评价口径

1. 排除 unknown 后，按提交 UTC 时间及 ID 排序，选择最接近前 70%／后 30% 的非空时间边界。同一时间点不跨越训练／测试两侧。
2. 非合成模式要求至少 1,000 个有效标签和 50 个正标签，并需独立时间契约；普通CSV/API缺少契约则拒绝训练。离线 `fit_temporal_baseline` 按固定截止审计后再检查数量，只拟合准入训练行、评价准入测试行。合成演示允许20个有效标签，元数据明确标签时间未检查。训练分区必须包含两类、测试分区非空。门槛是当前基线配置，不代表教师已确认的正式阈值。
3. StandardScaler 仅拟合训练特征。LogisticRegression 固定 `C=1`、`max_iter=1000`、种子 42，不进行超参数搜索或利用最终测试集选择阈值。
4. 登记训练／测试窗口、切分时间、数据哈希、特征顺序、配置、依赖版本、来源和标签策略。
5. Precision、Recall、F1 使用 0.5 阈值；ROC-AUC 在测试集只有一类时为 null，并提供原因。
6. 工作量使用 `max(1, LA + LD)`；零行变更按 1 个单位计，以避免零除。评价按 `概率 / 工作量` 排序，同分按 ID 确定顺序。
7. Recall@20%Effort 只取预算内完整提交的连续前缀，不拆分提交、不跳过前面的昂贵提交。若第一条已超预算，检查数和 recall 为 0；无正标签时 recall 为 null。
8. Popt 使用完整累计 recall 曲线的梯形面积，以 `标签 / 工作量` 的理想及最差顺序归一化；归一化分母为零时返回 null。此口径必须先与外部实现对齐，才可作跨实现数值比较。

界面风险队列按**概率降序**全局排序，再分页；该顺序与工作量评价顺序不同。高风险阈值为 0.7，低风险阈值为 0.3，中间为 medium，均登记在模型配置中。

默认队列为 `holdout`，包括切分点之后标签未知的提交；模型评价只使用该时间范围内有有效标签的测试提交。因此队列条数可能大于测试样本数。`All periods` 会额外展示训练期分数，并明确标为拟合检查。

解释是标准化特征乘逻辑回归系数的精确 **log-odds 贡献**：截距加全部贡献，再经过 sigmoid，可重建概率。界面展示最主要的五项，接口返回全部 14 项；它不是 SHAP，也不证明缺陷因果。未来模型需要各自匹配的解释方法。

## API

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/api/health` | 服务状态 |
| GET | `/api/datasets` | 数据集与来源统计 |
| POST | `/api/datasets/import` | multipart：file、name、provenance、label_policy、is_demo |
| POST | `/api/demo` | 幂等导入明确标记的合成示例 |
| GET | `/api/demo.csv` | 下载合成 CSV |
| POST | `/api/models/train` | JSON：dataset_id；同步训练固定基线 |
| GET | `/api/models?dataset_id=...` | 模型登记与可用状态 |
| GET | `/api/models/{id}/evaluation` | 两类指标、元数据和逐条测试分数 |
| GET | `/api/risks` | model_id、可选 dataset_id、page、page_size、min_probability、search、scope |
| GET | `/api/models/{id}/commits/{commit_id}` | 概率、特征、版本与精确解释 |

错误包括：数据不合法／不足为 422，数据或模型不存在为 404，模型与数据集不匹配或模型文件不可用为 409。API 不返回编造的默认概率。
