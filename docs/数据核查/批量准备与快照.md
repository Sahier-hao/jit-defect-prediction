# 批量准备与不可覆盖快照

单条[离线准备模块](离线准备模块.md)已接入 [preparation_batch.py](../../jit_defect/preparation_batch.py)。现在可以用一个清单核对多份保存的来源、查看每条资格／失败原因，并生成可重新读取、复算和核验的本地准备快照。

| AMQ-9330 / 8b6072d0 | 截止前已Bug / Resolved / Fixed | 本清单未提供目标分支集成证据 | unknown_integration |

## 直接运行与核验

在项目根目录、Python≥3.11环境中运行；只使用标准库。

```powershell
$prepared = python -m jit_defect.preparation_batch prepare `
  --manifest 'docs/数据核查/批量准备示例.json' `
  --snapshot-dir 'runtime/preparation-snapshots' | ConvertFrom-Json

$prepared.quality
python -m jit_defect.preparation_batch verify --snapshot $prepared.snapshotPath
```

相同输入会得到相同内容ID。示例保存的ID为`b750305c5fdde4a47b82f6d9035243b2f8bff2739a2f83648db1f8c40e775672`。快照文件包含配置、原清单／账本指纹、用到的来源、每条输入及其结果、唯一修复记录和质量摘要。改变截止点、清单原始字节或来源证据将形成新快照，旧文件保留。

`prepare`退出码0表示准备过程没有解析／来源失败，仍需查看候选与未知数量；退出码1表示保存了`prepared_with_errors`快照；非法共享配置、冲突重复或快照损坏返回2，不输出成功结果。`verify`核验内容ID、文件名和精确文件字节，成功返回0；它验证文件完整性，不宣布训练资格。

## 处理规则

所有输入必须有不同的ID。相同修复SHA和issue产生完全相同报告时，第二条输入保留`duplicateOf`，质量统计只计一次。若报告中的来源或集成断言冲突，则拒绝整批。不同SHA的cherry-pick仍是独立记录；集成断言属于其它分支时记为`excluded_branch`，不会自动推断跨分支修复族。

来源失败和解析失败各有原因计数；失败输入保存原patch／issue引用，正常输入仍处理。核算关系为：提交输入数＝非重复输入数＋重复数；非重复输入数＝成功解析数＋失败数；成功解析数＝候选数＋排除数＋未知数。

路径须留在清单目录及其来源子目录内，包括解析后的符号链接／目录联接。清单和账本及单份来源各限2MiB，最多1000条输入，总来源读取预算32MiB，单快照64MiB。失败来源消耗的读取字节也计入预算。

保存使用同目录临时文件、flush/fsync和原子不覆盖的硬链接创建；当前NTFS实际验证通过。已有同ID文件须先核验，损坏时拒绝复用并保留原文件。测试验证并发重放与抛异常时的临时文件清理，不计产品的进程崩溃恢复验收；不支持硬链接的文件系统会明确失败。
