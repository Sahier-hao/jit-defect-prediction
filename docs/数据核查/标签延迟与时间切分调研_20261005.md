# 标签延迟与时间切分调研

日期：2026-10-05。目标是把[设计草案](../需求与设计/产品设计文档.md)的“训练标签在截止前可得”落实成可测试行为。未采集新的仓库历史，未运行Git、SZZ或真实模型实验。

## 一手来源核对

| 来源（访问日期均为2026-10-05） | 本轮核对事实 | 对项目的影响 |
|---|---|---|
| [Song、Minku、Yao，On the validity of retrospective predictive performance evaluation procedures in just-in-time software defect prediction，EMSE 2023](https://link.springer.com/article/10.1007/s10664-023-10341-8) | §3.3说明提交发生与标签揭示之间有 verification latency；区分连续评价与回溯评价。在其13项目回溯实验中，等待时间对评价有效性的直接影响不显著。 | 要分别记录提交时间、标签时间与评价截止；不能泛化成“所有等待时间都导致评价失真”或“统一采用90天”。 |
| [An investigation of online and offline learning models for online Just-In-Time Software Defect Prediction，EMSE 2023](https://link.springer.com/article/10.1007/s10664-023-10335-6) | §3讨论延迟标签、等待期内未观察到缺陷的负例，以及后来发现缺陷时的标签更新；只用当前时点已可得的训练样本。 | 当前最终标签不能随意回填过去；没有历史标签版本时，采用保守排除。 |
| [Pornprasit、Tantithamthavorn，JITLine，2021 作者预印本](https://arxiv.org/abs/2103.07068) | 摘要指出在训练时使用整个训练与测试数据的设定不符合提交时预测情境。 | 时间审计不仅约束标签，也应明确特征信息截止；标准化仍只拟合已准入训练行。 |

本轮不照搬论文效果数字，也未复现论文。关于可得时间、成熟期与准入规则的实现属于本项目工程协议，不是以上论文共同规定的统一算法。

## 已验证的本地缺口

原 `fit_baseline` 先排除unknown，再按70/30提交时间切分。它没有标签可得时间字段；满足1000条与50正例后，普通非合成CSV可以进入训练。故即使训练提交时间早于测试，训练标签仍可能来自未来修复。

本轮新增失败测试先确认这个入口确实允许未经时间审计的训练，再实现拒绝。合成演示保留，模型元数据明确记录 `label_availability_checked=false`；这不是对真实标签延迟的验证。

## 本轮协议

CSV仍要求完整14维预计算特征，另加与精确CSV字节哈希绑定的JSON时间契约。固定 `trainCutoff` 和 `evaluationCutoff`，按提交时间先分队列，再逐行审计。训练标签在前者检查，测试标签在后者检查；标签过滤不会重新决定70/30边界。

每行保存 `featureAsOf`、标签状态、`labelAvailableAt` 与 `evidenceRef`。缺失证据／时间、晚于对应截止的标签、未来特征信息、未成熟负例或unknown都有明确排除理由。`featureAsOf`表示重构特征的信息截止，不是今天执行提取脚本的时间。它必须等于提交时点，避免用不完整或未来信息的声明冒充提交时特征。

成熟天数是显式整数参数；本轮合成软件夹具用1天便于手算，**不是对真实仓库的推荐**。产品草案的90天继续待Pilot。本协议要求 `clean_observed` 的证据时间已覆盖提交后的成熟期；它表示窗口内未发现归因，不保证永久无缺陷。

如果今天的正例标签在训练截止后才可得，本版本排除该训练行，不推测它当时是否已被标成clean。要复原clean→buggy修订，需独立历史证据与版本化标签事件，本轮未实现。

`evidenceRef` 是供复核的引用，尚未自动下载或证明内容真实性。审计证明的是**给定声明下的时间一致性**，不是上游SZZ质量或真实特征来源。审计快照因此继续 `trainingReady=false`。新增离线训练入口会在内部重做审计，普通非合成CSV/API训练则拒绝，避免缺失契约直接产生模型。

运行、格式、合成样例和本轮验证见[标签时间审计模块](标签时间审计模块.md)。小组真实访谈、需求定稿、文件策略复核、完整归因与正式数据训练仍待执行。
