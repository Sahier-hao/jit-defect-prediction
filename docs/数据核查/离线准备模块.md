# 离线修复候选准备模块

真实来源核查中的数据规则已落实到 [preparation.py](../../jit_defect/preparation.py)。它将保存的email文本补丁和Jira JSON转换为可复用的JSON报告：修复消息关联、原始差分计数、父版本删除行、截止时点issue状态、分支集成来源和候选判断。后续采集／SZZ可以使用这些输入；现有CSV试做仍要求完整预计算特征。

本地运行使用Python标准库，不访问网络，不执行Git，不修改输入。要求Python≥3.11；在项目根目录运行：

```powershell
$sample = 'docs/数据核查/activemq-2024-sample-20261004'
python -m jit_defect.preparation `
  --patch "$sample/fix-72befc14.patch" `
  --issue "$sample/AMQ-9481.json" `
  --as-of '2024-04-23T00:00:00Z' `
  --snapshot-at '2026-10-04T02:29:05.242191+00:00' `
  --target-branch 'main' `
  --integrated-at '2024-04-22T15:01:36Z' `
  --integration-source 'https://github.com/apache/activemq/pull/1206'
```

以上snapshot参数取自 [sources.json](activemq-2024-sample-20261004/sources.json) 的实际AMQ-9481获取时间；保存报告使用该条精确时间。`--integrated-at`、目标分支和来源是调用者明确提供的证据断言，模块不会自动抓取PR或验证集成关系。缺少集成时间或来源时，正常输出`unknown_integration`。

将`--as-of`改为`2024-04-22T00:00:00Z`即可查看截止前判断。输出到stdout；非法输入退出码2，诊断写stderr，不输出成功报告。可用`--help`查看参数。

## 历史规则与边界

完整历史先从当前字段逆向校验，再回放到截止时点。缺页、未提供changelog、截止点超出快照时间时保留未知；重复历史ID、时间无时区或字段链矛盾则拒绝。重新打开的issue失去当时的Fixed资格；后来改成Bug的issue，不能把Bug资格回填到此前。

真实AMQ-9461在2024年4月为Improvement，2024-06-02才改成Task，均不满足Bug-only条件。该事实由完整changelog回放测试覆盖；Task是当前快照值。

AMQ-9481的`resolutiondate`是15:07:37.766，历史Fixed／Resolved变更是15:07:37.776。既有[案例核查](ActiveMQ数据可行性核查.md)保留原始字段及其政策示例；本模块政策`jira-history-and-integration-v1`使用较晚的历史资格事件，并将原始resolutiondate单列。它是当前采集的历史重建，不能证明当年实际采集或观察到了该标签。

接受单个UTF-8 email文本补丁、无空白／引号的相对路径、普通文本增删和创建／删除文件；验证hunk计数、相对偏移、顺序和文件头。保留无末尾换行标记和cherry-pick来源。二进制、重命名／复制、纯mode改动、符号链接、组合diff、多补丁、危险或不支持的路径会明确失败。单份来源最大2MiB。

当前没有自动处理merge／backport去重，没有Java词法分析或SZZ，没有历史特征和训练数据导出。`candidate`只表示此政策下的待归因修复候选；`inducingLabel`始终为null，既不等于buggy，也不等于clean。

后续已增加[批量入口、质量摘要与不可覆盖快照](批量准备与快照.md)，复用本模块并处理完全一致的重复输入；跨分支修复族推断仍待实现。
