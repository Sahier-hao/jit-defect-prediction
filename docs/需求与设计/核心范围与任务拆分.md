# 核心范围与任务拆分

版本：v0.6草案，2026-10-04。以下是为四人初学者团队准备的收敛建议，**不是已经召开评审或团队同意的结果**。原42条Story和18/17/7优先级保留；重要性与本期选入范围分开。

## 1. 收敛范围

建议从原35条最终候选收敛到**24条业务故事+2条过程故事**，保留课程真实仓库、SZZ、Kamei14、经典/深度两类总计≥8模型、双指标、预测/解释、风险列表、历史趋势和两项质量验证。课程最低20条关联核心故事，24条业务候选留有余量。

首轮链路候选16条，最终补足其余8条业务；首轮US-3.1.1只验收一个基线，完整多方法验收在最终核心扩展完成。两条过程故事贯穿全程。

风险分级、批量接口、时间/阈值高级筛选、目录分布在这版核心范围中暂缓。现有五页原型仍展示这些候选席位，已加范围注记；最终选中列表以本文件和PRD v0.6为准。

## 2. 可认领的小任务

时间仅为首次尝试估计，可根据初学者实际理解调整；访谈需等真实对象安排。负责人/复核人/日期不预填，也不替队友派发。

| Task | 首次估计 | 工作 | 依赖 | 完成产物 | 完成标准 | 父任务 / OpenSpec task |
|---|---|---|---|---|---|---|
| R-01 | 30分钟 | 核对课程与一页概要 | 无 | 按条款记录遗漏或疑问 | 每项意见说明来源；不得以作者自查替代非作者实际核对。 | P-01 / 1.1 |
| R-02 | 20分钟 | 准备真实访谈对象与安排 | R-01 | 对象类型、相关经历、实际联系人和约访安排 | 优先有真实评审经验；实际联系由团队执行，不虚构已同意参与。 | P-02 / 1.2 |
| R-03 | 30分钟 | 开展一位真实用户访谈 | R-02 | 一份匿名访谈记录 | 按模板记录真实经历、原话和反例；计划3–5位，每位复制此任务。 | P-02 / 1.2 |
| R-04 | 45分钟 | 汇总访谈并回填用户场景 | R-03 | 假设支持/反对表与PRD修订建议 | 实际人数、日期、原始证据与分歧可追溯；没有行为证据就保持待验证。 | P-02 / 1.2 |
| R-05 | 30分钟 | 讨论24条业务核心范围 | R-01 | 选中/暂缓Story及理由 | 保留课程硬性要求；这次讨论若早于访谈，只能记录为初步意见，R-04后复核。 | P-03 / 1.3 |
| R-06 | 60分钟 | 交叉复核核心故事验收 | R-05 | 按Story-ID整理的正常/异常检查表 | 24条业务和2条过程均有意见；无默认分数、假解释或凭草案宣布通过。 | P-04 / 2.1 |
| R-07 | 45分钟 | 核算标签与指标边界例 | R-01 | 验收测试设计中的手算记录及未决参数 | 能核对训练标签可得时间、Precision/F1/AUC和20%预算；不使用业务实现生成期望值。 | P-05 / 2.2 |

| R-10 | 30分钟 | 确定两项质量验证方案 | R-07, R-08 | 选型、环境、采样、计时和失败统计 | 有可执行测量条件；200次/2秒/30分钟等仍需资源核对，不提前写达标。 | P-08 / 2.5 |

## 3. 使用方式

[离线评审工作页](../团队协作/评审/评审工作页.html)读取同一份准备计划生成；可在浏览器打开，填写负责人、意见和证据后导出记录。它不会发给队友，也不代替课程指定平台看板。默认所有实际活动未认领、所有决定未讨论。

[项目一页概要](../团队协作/项目一页概要.md)用于讨论开场；[验收测试设计](验收测试设计.md)给出手算数据和预期结果；[机器可读准备计划](../团队协作/评审/准备计划.json)保存全42条范围标签与12张任务卡。

修改选中范围时同步PRD、设计、OpenSpec与原型注记。将来若要重新加入暂缓Story，需记录真实理由和新增工作量，不能因为界面有一个占位就当作本期承诺。
